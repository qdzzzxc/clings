# Решение задачи как на контрольной

Промпт для Claude: вставь его, а после — условие задачи (или файл
из `exercises/`). Ответ — только код, написанный так, как его надо
сдать на контрольной.

---

Реши задачу на C так, как её решают на контрольной по C: от руки,
без IDE и без подсказок. Ниже — правила преподавателя. За нарушение
любого из правил 1–4 задание оценивается в 0 баллов.

## Обязательные правила

1. Каждая переменная инициализируется при объявлении:
   `int count = 0;`, `char* p = NULL;`, `char line[LINE_SIZE] = "";`,
   `struct timespec ts = { 0, 0 };`. Никаких `int i;` без значения,
   в том числе в `for`: `for (size_t i = 0; ...)`.
2. Параметр-указатель, по которому функция ничего не пишет, —
   указатель на `const`: `const int* arr`, `const char* s`,
   `const Node* head`, `const int m[][COLS]`. `FILE*` не трогать.
3. Каждый `malloc`/`calloc`/`realloc` имеет парный `free`, каждый
   `fopen` — парный `fclose`, каждый `open` — `close`, на всех путях
   выхода из функции, включая ошибки.
4. Код отформатирован в стиле WebKit (`clang-format`): отступ
   4 пробела, `{` функции на новой строке, `{` у `if`/`for`/`while`
   на той же строке, фигурные скобки у каждого `if`/`for`/`while`,
   даже из одной строки, `int* p` — звёздочка у типа.

## Работа с файлами

- Строки читать целиком: `fgets(line, sizeof(line), in)` в буфер.
  Не читать по символу через `fgetc`, если строку можно прочитать
  целиком.
- '\n' убирать одной строкой: `line[strcspn(line, "\n")] = '\0';`.
  Без цикла по строке в поисках '\n' и без проверок вида
  `line[strlen(line) - 1] != '\n'`.
- Файл читать один раз. Не запоминать позицию начала строки, чтобы
  потом вернуться к ней через `fseek`/`rewind` и перечитать: нужную
  строку сразу копировать в отдельный буфер (`strcpy`).
- Выводить строку целиком (`fputs`/`fprintf`), а не по символу.
- Результат `fopen`, `malloc`, `fscanf`, `fgets` проверять.

## Стиль

- Только код: без комментариев, без пояснений до и после, без
  отладочного вывода. Если в условии есть `main` — оставить его как
  в условии, свой не дописывать.
- Сигнатуры функций и имена — ровно как в условии.
- Ограничения из условия («массивы запрещены», «одним проходом»,
  «через `memmove`») соблюдать буквально.
- Стандарт C17, код собирается с
  `-Wall -Wextra -Werror -Wpedantic` и проходит AddressSanitizer
  и UBSan: без выхода за границы, утечек и переполнений.
- Размеры и индексы — `size_t`. Цикл вниз по `size_t` не писать
  как `for (size_t j = n - 1; j >= 0; j--)`: он бесконечный.
  Писать `for (size_t j = n; j > 0; j--)` и обращаться к `arr[j - 1]`.
- Суммы и произведения, которые могут не влезть в `int`, считать
  в `long long` (или `unsigned long long`).
- Простой прямой код без лишних функций, макросов и «умных» трюков:
  так, как успеваешь написать на листке.

## Перед ответом проверь

- [ ] у каждого объявления есть `=`;
- [ ] каждый указатель-параметр, по которому не пишут, — `const`;
- [ ] на каждый `malloc`/`fopen` есть `free`/`fclose` на всех путях;
- [ ] нет `fgetc` там, где хватает `fgets`, и нет `fseek`/`rewind`
      ради перечитывания;
- [ ] нет комментариев.
