# Темы

Темы идут в порядке курса, задачи внутри темы — от простых к сложным.

| Тема | Задач | Что тренируется |
| --- | --- | --- |
| `00_basics` | 7 | Целые типы, битовые флаги, циклы, массивы, указатели, C-строки, `argc`/`argv` |
| `01_files` | 4 | `fgetc`, `fscanf`, `fgets`, `fprintf`, двоичные файлы через `fread`/`fwrite` |
| `02_memory` | 6 | `static`, двумерные массивы, `malloc`/`realloc`/`free`, алгоритмы над строками |
| `03_debug` | 3 | Поиск ошибок в готовом коде: память, логика, медленный код |
| `04_structs` | 5 | `struct`, `typedef`, указатели на функции, `qsort`, связный список |
| `05_modules` | 2 | Заголовки, раздельная компиляция, `static`/`extern`, свой Makefile |
| `06_graphs` | 4 | Матрица смежности, BFS, DFS и топологическая сортировка, Дейкстра |
| `07_optimization` | 4 | Префиксные суммы, двоичный поиск, сортировка и два указателя, быстрая степень |
| `08_testing` | 2 | Написать проверки для чужой функции |

## Чем отличаются некоторые темы

- **`03_debug`.** В файлах нет TODO: код уже написан, но с ошибками.
  Их нужно найти по отчётам санитайзера и упавшим тестам.
- **`05_modules`.** Задача — не файл, а каталог. В нём лежит готовый
  `main.c` с условием, а модули и `Makefile` нужно создать самому.
- **`07_optimization`** и последняя задача `03_debug`. Тесты ограничены
  по времени: слишком медленное решение завершается с сообщением `Too slow`.
- **`08_testing`.** Писать нужно не функцию, а проверку для неё.

## Без автоматической проверки

Последняя тема курса — CI в GitLab — тестами не проверяется. Упражнение:
добавь в свою ветку `.gitlab-ci.yml`, который на каждый коммит запускает
`make check`.
