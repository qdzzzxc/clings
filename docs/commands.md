# Команды и устройство проекта

## Требования

GCC, GNU Make, POSIX shell и стандартные утилиты Unix.
Для `make format` дополнительно нужен clang-format.

## Структура

```text
exercises/  — заготовки и рабочие файлы на время решения
templates/  — исходные шаблоны с TODO и тестами
solutions/  — сохранённые решения, включаются в Git
.backups/   — резервные копии перед перезаписью (исключены из Git)
.build/     — программы и журналы проверок (исключены из Git)
scripts/    — небольшой shell-скрипт для команд Makefile
```

`templates/` меняются только при разработке упражнений. Команды запуска,
форматирования, сохранения и сброса их не редактируют.

## Команды

| Команда | Действие |
| --- | --- |
| `make run 0 2` | Собрать и запустить упражнение |
| `make test 0 2` | Собрать с `-DTEST` и запустить встроенные тесты |
| `make format 0 2` | Отформатировать рабочий файл через clang-format |
| `make reset 0 2` | Сохранить рабочий файл в `.backups/` и восстановить шаблон |
| `make reset-all` | Так же восстановить все упражнения |
| `make save 0 2` | Скопировать рабочий файл в `solutions/` |
| `make check 0` | Проверить все упражнения темы 0 |
| `make check` | Проверить все темы |
| `make stats` | Показать статус каждой задачи, прогресс по темам и общий итог |

Номера можно писать как `0 2` или `00 02`. За один вызов Make выполняется
одна команда. Аргументы программы передаются отдельно:

```sh
make run 0 6 RUN_ARGS="10 -3 7 5"
```

`reset` и `reset-all` никогда не меняют `solutions/`.
`save` копирует текущую работу в `solutions/` и дополнительно в `.backups/`.
Если сохранённое решение уже существует, его прежняя версия тоже попадает
в `.backups/` перед перезаписью.
Резервные копии имеют уникальные имена и сохраняют путь темы и задачи.

`check` продолжает проверку после ошибки, выводит PASS/FAIL для каждой задачи
и итог. Если есть FAIL, команда возвращает ненулевой код. Подробности ошибок
лежат в `.build/<тема>/*.log`. Файлы без встроенных тестов получают SKIP и не входят
в число проверенных задач; `make test` для них сообщает об отсутствии тестов.

`make stats` заново запускает тесты: если есть сохранённое решение в
`solutions/`, проверяет его; иначе проверяет рабочий файл в `exercises/`.
Решённой считается задача со статусом PASS. Поэтому сброс заготовок
не обнуляет прогресс сохранённых решений. Для каждой темы и всего проекта отображаются шкала, количество
решённых задач и процент. FAIL означает ошибку сборки или тестов, MISSING —
отсутствие рабочего файла, SKIP — отсутствие тестов. В статистике все задачи
входят в общее количество, но только PASS считается решённой.
Команда подсказывает первую задачу с FAIL/MISSING и возвращает успешный код,
даже когда решено ещё не всё. Журналы проверок лежат в `.build/<тема>/`.

## Решения и Git

Решения и заготовки хранятся в одной ветке и синхронизируются через Git.
Для каждой задачи:

```sh
# Реализуй TODO в exercises/00_basics/06_cli.c
make test 0 6
make save 0 6
make reset 0 6
make stats
```

После `save` ответ хранится в `solutions/`, а `reset` возвращает в
`exercises/` чистый шаблон. Затем самостоятельно добавь и закоммить изменения.
Так в Git остаются заготовки и ответы в отдельных каталогах.
`make check` и `make test` проверяют рабочие файлы, `make stats` учитывает
сохранённые решения. Отдельная ветка для решения задач не обязательна.
